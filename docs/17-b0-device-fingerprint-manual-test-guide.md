# B0 设备指纹手动测试指南

[上一篇：B0 设备指纹与安全原型报告](16-b0-device-fingerprint-and-security-prototype-report.md) | [返回索引](README.md)

> 本指南用于 B0 受控手动验收。测试工具是独立 EXE，不会安装 DeviceId 到正式 NetRelay，不会修改正式客户端配置，也不会上传报告。

## 1. 测试工具

统一发布位置：

```text
artifacts/b0-deviceid-test-tool/win-x64/NetRelay.B0.DeviceIdTestTool.exe
```

双击 EXE 会在同目录 `reports/` 文件夹生成一份报告。

报告包含稳定的应用域隔离哈希，用于比较前后证据变化。它不包含原始序列号、原始接口 GUID、原始 MAC、网卡型号、用户名或机器名，但仍应视为敏感文件：

- 不上传到公开仓库。
- 不发送给无关人员。
- 测试完成后可删除。
- 程序不会自动上传报告。

## 2. 命令

生成带标签报告：

```powershell
.\NetRelay.B0.DeviceIdTestTool.exe --label "当前电脑-基准"
```

指定输出：

```powershell
.\NetRelay.B0.DeviceIdTestTool.exe --label "更换网卡前" --output .\reports\before.json
```

比较报告：

```powershell
.\NetRelay.B0.DeviceIdTestTool.exe --compare .\reports\before.json .\reports\after.json
```

也可以在资源管理器中同时选中两份 JSON 报告，将它们拖到 `NetRelay.B0.DeviceIdTestTool.exe` 上进行比较。

查看帮助：

```powershell
.\NetRelay.B0.DeviceIdTestTool.exe --help
```

## 3. 报告说明

原始报告包含：

- 报告和指纹算法版本。
- 工具版本、UTC 生成时间、测试标签和 Windows 版本。
- 采集耗时。
- DeviceId 核心硬件分类哈希。
- NetRelay 物理候选网卡辅助分类哈希。

比较报告只包含：

- 各分类前后数量。
- 匹配、增加和移除数量。
- 核心硬件与网卡辅助分类匹配数。
- 初步测试结论。

比较结论只用于 B0 研究，不能直接作为正式封锁判定。

## 4. 测试顺序

### 4.1 当前电脑短期稳定性

1. 生成 `baseline-1.json`。
2. 等待一分钟并再次生成 `baseline-2.json`。
3. 比较两份报告。

通过标准：核心硬件与网卡辅助分类全部一致。

### 4.2 禁用和启用网卡

1. 生成禁用前报告。
2. 禁用不承载当前网络的 VMnet1 或测试网卡。
3. 生成禁用中报告。
4. 重新启用网卡并生成恢复后报告。
5. 分别比较。

预期：动态链路状态不进入指纹；物理候选分类不应因临时禁用而无解释地变化。VMnet1 属于虚拟接口，应始终被排除。

当前进度：2026-06-13 已完成网卡禁用状态与恢复状态比较，结果为核心硬件 `6/6`、网卡辅助 `3/3` 完全一致，此项通过。

补充结果：第二台物理设备禁用一个物理网卡后再恢复，核心硬件仍为 `6/6`；恢复后 GUID、MAC 和型号三个网卡辅助分类各新增一项。比较摘要中的网卡辅助 `3/3` 仅表示三个分类都有重叠，不表示分类内全部证据一致。该结果证明网卡证据只能作为动态辅助证据。

### 4.3 抓包检查

1. 使用 Wireshark 在所有活动接口开始抓包。
2. 记录开始时间。
3. 运行测试工具生成报告。
4. 停止抓包并检查该时间范围。

通过标准：测试工具没有主动执行 ARP 扫描、邻居发现、Wi-Fi 扫描、局域网端口连接、DNS、HTTP 或其他外部网络请求。

DeviceId 读取本机 WMI 和注册表可能产生本机系统活动，但不应产生外部网络流量。

当前进度：2026-06-13 用户使用 Wireshark 抓包确认通过，未发现外部网络扫描流量。DeviceId 版本或采集范围变化后需要重新验证。

### 4.4 虚拟机测试

建议使用快照：

1. 创建虚拟机基准报告。
2. 克隆虚拟机后生成报告。
3. 更换虚拟网卡后生成报告。
4. 更换或新增虚拟硬盘后生成报告。
5. 恢复快照并重新生成报告。

记录每类核心证据和网卡证据的变化。虚拟机克隆不得仅凭网卡证据被自动识别为同一物理设备。

### 4.5 物理硬件变化测试

在具备安全条件时执行：

- USB 网卡或物理网卡更换。
- 系统盘更换。
- 另一台物理电脑生成报告。

这些测试用于确定最终匹配权重，不要求在当前主力电脑上冒险执行。

### 4.6 跨设备误匹配检查

1. 分别在两台物理设备生成稳定基准报告。
2. 使用 `--compare` 比较两台设备的报告。
3. 检查核心分类、网卡辅助分类及逐项匹配数量。

通过标准：不同设备不会因共享网卡型号或其他少量辅助证据而被自动认定为同一设备。

当前进度：2026-06-13 已完成两台物理设备交叉比较。核心证据为 `0/6`，网卡辅助为 `1/3`，唯一重叠来自共享网卡型号；工具正确判定为不同设备。该结果仅代表初始两设备样本通过，最终阈值仍需更多物理设备与虚拟机样本。

### 4.7 已取消的测试

维护者于 2026-06-13 决定取消以下 B0 手动测试，两项不阻塞 B0：

- 非管理员或受限 WMI 权限异常测试。
- Windows 重装后的原设备连续性测试。

重装系统与换设备并不完全等价：Windows 标识可能变化，但主板、CPU 等硬件通常仍相同。取消测试意味着正式系统暂不保证重装后自动关联到原设备，后续可将其视为新安装实例处理。

## 5. 结果记录

每次测试需要记录：

| 项目 | 内容 |
| --- | --- |
| 日期 | 测试执行日期 |
| 环境 | Windows 版本、物理机或虚拟机 |
| 场景 | 基准、禁用网卡、换网卡、克隆、重装等 |
| 报告标签 | 工具中的 `--label` |
| 比较结果 | 核心匹配数、网卡匹配数和变化分类 |
| 结论 | 通过、失败或需要调整 |
