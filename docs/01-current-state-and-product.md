## 1. 现状审计

### 已确认

当前已经完成第五阶段（稳健运行）的主要功能开发。当前代码已通过 Release 构建和仓库内回归测试；真实网卡切换、休眠恢复与不同 Windows 版本仍需真机验收。

当前已实现：

- C#、.NET 8、WPF 与 XAML 原生桌面工程。
- `NetworkInterface` API 读取网卡名称、描述、类型、链路状态、速度、MAC 和 IP 地址。
- WPF 液态玻璃概览页面支持扫描、刷新、选择网卡和查看基础详情。
- 网卡列表每秒采样系统累计收发字节，显示实时收发速率和最近约 30 秒流量波形，帮助区分真正承载流量的接口。
- 根据接口类型和名称/描述关键词显示“物理候选”“疑似虚拟”“系统环回”或“隧道 / VPN”启发式标签。
- 通过 Windows Network Connections COM 接口按 GUID 启用或禁用网卡，不调用 PowerShell 或 `netsh`。
- 禁用前显示原生确认对话框，操作期间防止重复点击，完成后刷新状态并展示结果或 Windows HRESULT。
- 禁用后即使 `.NET NetworkInterface` 不再返回该接口，也会从 Windows Network Connections 原生枚举补回列表；原生枚举短暂漏项时会保留最近状态，避免列表项立即消失并允许重新启用。
- 支持 `--diagnose-adapters` 只读诊断模式，生成包含 .NET 与 Windows Network Connections 两套枚举结果的本地 JSON 报告，不启用或禁用任何网卡。
- 应用清单声明 `requireAdministrator`。
- Windows 11 使用 DWM Mica 和原生圆角；Windows 10 使用 WPF 半透明降级。
- 已验证生成原生 `NetRelay.exe`，且启动期间不会创建 WebView2 进程。
- 程序设置界面增加了开机自启复选框，通过 Windows 任务计划程序创建当前用户登录时以最高权限运行的固定启动任务；读取状态时会校验任务仍指向当前 EXE 与 `--startup` 参数。
- 主程序在通过 `--startup` 命令行参数自启动时，能够无闪烁地直接启动并隐藏至系统托盘运行。
- 倒计时预警悬浮卡片的延迟按钮文本已完成格式化优化，能正确且清晰地显示为“延迟 10 分钟”。
- **扁平磨砂玻璃控件重塑**：重构并统一了全局按钮样式（`SoftButtonStyle`/`PrimaryButtonStyle`/`DangerButtonStyle`），实现了基于半透明渐变、白色反射边缘和有色外发光环境光影的高通透度毛玻璃质感，配合局部隐式 `TextBlock` 穿透重载，彻底消除了 WPF 默认字体颜色样式覆盖导致的视觉混乱；同时对 `CheckBox`、`ComboBox`、彩色图标底框进行了全面的磨砂玻璃扁平化升级，确保了界面视觉风格的 100% 连贯性。
- **单进程内部异常隔离与优雅退出**：
  - **完全退出原则**：不引入独立的后台守护进程，确保应用关闭时所有工作线程（例如 `MainViewModel` 的探测/刷新任务、`RuleSchedulerService` 的调度线程等）立即终止，实现无进程残留退出。
  - **异常安全隔离**：对 Windows 原生 COM 接口调用与网络状态获取增加更周密的异常捕获隔离，杜绝了偶发系统 API 错误或拔插网卡瞬时越界引发主进程意外崩溃的风险。
  - **异步任务优雅取消**：应用退出时，通过 `CancellationToken` 立即安全中止正在进行的后台 HTTP/HTTPS 探测与状态刷新任务，确保进程退出响应瞬时完成。
- **日志自动滚动与容量清理 (Log Rotation)**：
  - 后台静默执行日志文件清理，自动扫描 `%LOCALAPPDATA%\NetRelay\logs\` 目录下的历史日志文件，并将超过 30 天的 `execution-*.jsonl` 日志物理删除，完全不需要用户手动干预。

### 未来规划与路线图

基于与开发团队的沟通，以下功能已被列入项目的后续演进路线图：

1. **核心联网探测能力扩展**：
   - **多协议网络探测（ICMP Ping 与 DNS 校验）**：支持向公共 DNS（如 `223.5.5.5`）发送 ICMP 报文，以及执行 DNS 解析探测，作为 HTTP 探测的底层备份判定。
   - **后端辅助校验（DNS 域名解析）**：在后续接入后端服务时，客户端可向后端接口发起 API 请求/域名解析，检查真实端到端联网可用性。
   - **Windows NLM/NCSI 接入**：读取系统级网卡状态指示器，当系统报告“无 Internet 访问”时，自动补充为规则判定条件。
2. **日志自动滚动与容量清理（Log Rotation）(已在第五阶段实现)**：
   - 限制 `%LOCALAPPDATA%\NetRelay\logs\` 目录下日志文件的最大存储天数（30天），到期自动清理过期日志，避免磁盘占用膨胀。
3. **可交互式 Windows Toast 富通知**：
   - 规则预警时发送包含“延迟 10 分钟”、“取消本次”等快捷按钮的 Windows Toast 通知，允许用户无需打开主界面即可直接控制规则调度。
4. **网卡防抖策略与冷却配置的可视化**：
   - 在设置界面中提供直观的滑动条（Slider）或输入框，允许用户自由配置防抖时间（Debounce）、冷却时间（Cooldown）等调度参数。
5. **引导式安装包（Installer）**：
   - 在开发的最后阶段，引入 WiX Toolset 或 Inno Setup，自动引导 .NET 8 Desktop Runtime 的检测与安装，并规范化配置开机自启的任务计划。
6. **单进程内部异常隔离与优雅退出 (已在第五阶段实现)**：
   - **完全退出原则**：不引入独立的后台守护进程，确保应用关闭时所有工作线程立即终止，实现无残留退出。
   - **异常安全隔离**：对 Windows 原生 COM 接口调用与网络状态获取增加更周密的异常捕获隔离，避免偶发系统 API 错误或网卡插拔瞬时越界引发主进程意外崩溃。
   - **异步任务优雅取消**：应用退出时，通过 `CancellationToken` 立即安全中止正在进行的后台 HTTP/HTTPS 探测与状态刷新任务，确保进程退出响应瞬时完成。

## 2. 项目定位

**计划实现。** NetRelay 是面向 Windows 10/11 x64 用户的本地网络适配器管理工具，解决以下场景：

- 校园有线网络在固定时间断网，但 Windows 仍认为有线链路有效，导致已连接的手机热点无法正常承担互联网流量。
- 用户不希望每晚进入控制面板手动禁用有线网卡。
- 用户需要在禁用、恢复和自动切换前得到明确通知，并能够撤销、延迟或取消操作。
- 用户需要在本来已经断网的情况下继续管理网卡，而不是因联网探测失败而阻止操作。

目标用户是能理解“网卡启用/禁用”含义、但不希望编写 PowerShell 或操作任务计划程序的 Windows 用户。

## 3. 产品目标与边界

### 首版目标

- 展示电脑上的网卡及其启用、链路、IP、默认路由和互联网状态。
- 允许用户选择目标网卡并一键启用或禁用。
- 支持一次性、每日、每周和网络状态变化自动化规则。
- 为每条规则配置多个提前通知时间。
- 通过连续探测识别“网线仍连接但实际无法访问互联网”。
- 自动切换前验证备用网卡可用，避免让电脑彻底离线。
- 记录规则执行、跳过、失败和恢复历史。

### 首版不包含

- Windows 服务、远程控制、云同步、账号系统或多用户协作。
- macOS、Linux、Windows ARM64 支持。
- VPN 配置、路由表编辑器、代理设置或校园网认证客户端。
- 以 `ping` 结果作为自动切换的唯一判断。
- 自动绕过学校网络政策或认证限制。

## 4. 主要用户流程

```mermaid
flowchart TD
    A[启动 NetRelay] --> B[扫描并展示网卡]
    B --> C[用户选择校园网网卡]
    C --> D{操作方式}
    D -->|立即操作| E[确认后启用或禁用]
    D -->|创建规则| F[配置触发时间或网络条件]
    F --> G[配置提前通知与恢复策略]
    G --> H[保存配置并装载至调度器]
    H --> I[到点或条件变化]
    I --> J[探测目标与备用网络]
    J --> K{满足保护条件}
    K -->|是| L[执行操作并通知]
    K -->|否| M[跳过操作并通知原因]
```

## 5. 成功标准

- 用户能在两次点击内对已选网卡执行启用或禁用。
- 即使目标网卡已经没有互联网，手动操作仍可执行。
- 自动化规则与自动恢复动作在主窗口关闭（隐藏至托盘）后仍能正常由后台服务监听并执行。
- 条件变化规则不会因短暂网络抖动（防抖延时）反复切换。
- 自动禁用前能验证存在可用的备用互联网连接。
- 每次自动化行为及被拦截原因都能从结构化执行日志中解释。
