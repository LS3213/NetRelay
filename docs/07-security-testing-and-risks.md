# 安全、测试与风险

[上一篇：开发与运维](06-development-and-operations.md) | [返回索引](README.md)

> 规则引擎、调度服务与液态玻璃 UI 的主要功能已实现，并包含不操作真实网卡的回归测试。真实网卡控制、自动回滚、休眠恢复与跨 Windows 版本行为仍需专用测试机验收。

## 1. 安全边界

NetRelay 能禁用网络适配器且始终以管理员权限运行，错误实现可能导致系统离线或扩大高权限攻击面。

必须遵循：

- 仅允许操作重新枚举后仍存在的接口 GUID。
- 手动启用/禁用通过 Windows `INetConnection` COM 接口执行，不生成或执行 Shell/PowerShell 命令。
- UI 输入、配置文件和参数全部视为不可信。
- 不执行用户提供的 Shell、PowerShell、任意程序路径或任务参数。
- 所有的自动化规则及延迟恢复完全由程序内联的后台调度线程托管，不写入系统层级任务计划。
- 主程序使用当前用户会话范围的单实例锁；重复启动仅唤醒现有窗口，不创建第二个调度器。
- 规则引擎按规则 ID 与目标网卡 GUID 串行执行，避免并发切换冲突。
- 配置写入采用临时文件与原子替换；损坏配置会被归档并替换为不含规则的默认配置，当前不保留最近有效备份。
- 自动禁用前验证备用互联网；执行后失败则立即回滚。
- 配置损坏、版本未知或校验失败时暂停自动化。
- 无效探测策略返回 `PROBE_POLICY_INVALID`，不会因零轮探测或非法阈值被误判为在线。
- 日志避免凭据、完整响应正文和不必要的个人网络信息。

## 2. 权限与通知风险

始终管理员运行简化了网卡控制，但也意味着 WPF UI 处于高权限进程。

首版缓解措施：

- 应用服务采用最小权限和参数白名单。
- 禁止任意 Shell、PowerShell 和 URL 打开能力。
- 外部链接交给经过校验的系统浏览器入口。
- 设置严格内容安全策略，不加载远程脚本。
- 通知操作只携带短 ID，所有真实参数从本地配置重新解析。

长期建议：评估拆分普通权限 UI 与受限高权限辅助进程，缩小高权限攻击面。

## 3. 测试分层

| 层级 | 范围 | 要求 |
| --- | --- | --- |
| C# 单元测试 | 规则评估、连续失败、冷却、迁移、错误映射 | 不操作真实网卡 |
| 前端单元测试 | 页面状态、规则表单、危险操作确认 | 使用模拟命令 |
| 集成测试 | 配置、内联调度、日志 | 使用临时目录和模拟 Windows 接口 |
| Windows 真机测试 | 网卡控制、通知、休眠恢复 | 使用专用测试机 |
| 发布验收 | 安装、升级、卸载、签名、SmartScreen | Windows 10/11 x64 |

当前仓库包含 `tests/NetRelay.RegressionTests` 回归测试可执行项目，覆盖不需要真实网卡的核心策略与单实例行为。VMnet1 禁用、列表保留与恢复已完成受控实机验收；物理网卡切换、切换后回滚和 Windows 通知仍必须在专用 Windows 测试环境验收。

## 4. 核心验收矩阵

| 场景 | 预期结果 |
| --- | --- |
| 有线链路显示连接但双端点连续失败 | 识别为无互联网，不被链路状态误导 |
| 手机热点可联网 | 自动禁用校园网后复检互联网成功 |
| 手机热点已连接但无法联网 | 跳过自动禁用并发送通知 |
| 所有网络均断开 | 只通知，不自动禁用目标网卡 |
| 单次 HTTP 超时 | 不立即判定断网 |
| 网络快速反复变化 | 防抖且冷却期内不重复执行 |
| 单次调度扫描超过 5 秒 | 下一次 Timer 回调跳过，不并发扫描或重复通知 |
| 多个虚拟网卡均显示已连接 | 使用分类标签、实时速率与波形帮助识别实际活跃网卡 |
| 目标网卡显示名称变化 | 规则仍通过 GUID 找到目标 |
| 目标网卡被删除 | 暂停相关规则并说明原因 |
| 目标网卡已经禁用 | 再次禁用视为幂等成功 |
| 禁用后 `.NET` 或原生枚举短暂漏项 | 使用最近原生状态保留列表项，连续多次缺失后再移除 |
| 禁用按钮连续点击 | 操作期间禁用按钮，不创建并发网卡操作 |
| 主窗口关闭（隐藏至托盘） | 所有的内联定时与网络监听规则照常触发 |
| 托盘进程（程序进程）完全退出 | 所有的自动化监控与延迟自动恢复终止 |
| 电脑休眠错过时间 | 唤醒后内联调度器即时评估并在需要时补偿执行 |
| 通知选择延迟 | 只延迟本次，不修改规则 |
| 通知选择取消本次 | 执行入口跳过并记录取消 |
| 禁用后复检失败 | 立即尝试重新启用并通知 |
| 配置文件损坏 | 归档损坏文件并创建不含规则的默认配置，不执行未知规则 |
| 开机自启任务创建失败 | 保持原配置状态并向用户显示错误 |
| 程序移动后开机自启任务仍指向旧路径 | 设置页识别为未启用，重新勾选后重建任务 |
| 查询任务计划程序失败 | 设置页安全显示为未启用，不因查询异常崩溃 |

## 5. 接口与数据测试

- 所有应用服务方法验证 GUID、UUID、范围、枚举值和权限。
- CLI 对未知参数、缺失值、超长值和注入字符返回失败。
- 配置迁移覆盖每个旧版本到当前版本。
- JSONL 日志在进程异常退出后仍能读取既有完整记录。
- 规则创建、修改和删除即时热重载到调度器服务中。
- 时间按本地时区、夏令时变化和系统时间调整进行测试。

## 6. 已知限制

- 条件变化规则依赖托盘进程，托盘未运行时无法监听。
- 双端点均可能被地区网络、校园网、代理或防火墙屏蔽。
- 源 IP 绑定不一定足以控制 Windows 实际出口，必须验证实际接口。
- VPN、虚拟交换机和复杂路由环境可能影响备用网卡识别。
- 物理/虚拟网卡分类属于启发式判断，驱动名称异常或未命中关键词时可能分类不准确；流量波形只表示活动度，不证明该接口可访问互联网。
- 未签名的高权限程序会触发信任和分发问题。
- 只读诊断报告包含网卡 GUID、名称和设备描述，用户分享报告前需要检查设备识别信息。
- Windows 通知操作与高权限应用的激活兼容性尚未确认。
- 首版没有 Windows 服务，因此无法在用户未登录时监听网络变化。

## 7. 技术债与改进建议

按优先级：

1. 实现后评估普通权限 UI 与高权限辅助进程拆分。
2. 建立 Windows 10/11 多版本和多网卡真机测试环境。
3. 为复杂路由、VPN 和代理环境提供可解释的诊断视图。
4. 提供端点健康度统计，避免长期失效端点造成误判。
5. 评估应用签名、自动更新与更新签名验证。
6. 在用户明确同意后，考虑匿名崩溃报告；首版默认不上传遥测。

## 8. 未确认事项

- 网卡启用/禁用所采用的具体 Windows API 及其跨版本行为。
- Windows App SDK/WinRT 通知在非打包 WPF 管理员应用中的激活行为。
- Windows 任务计划程序在管理员应用、通知入口和不同登录状态下的最佳配置。
- 默认双端点在目标用户网络中的成功率、隐私接受度和响应稳定性。
- 复杂校园认证、透明代理和强制门户对主动探测的影响。
