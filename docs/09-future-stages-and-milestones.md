## 详细开发计划

### 1. 第五阶段：稳健运行 (Robustness) (已实现)

#### 目标
聚焦于程序的健壮性，确保程序在面对复杂的 Windows COM API 错误时不会意外闪退，并且在用户选择“关闭”时，能够 100% 干净、顺时且无进程残留地完全退出，同时解决日志无限堆积的存储隐患。

#### 核心任务
1. **Windows COM API 异常隔离 (Try-Catch 强化)**
   - **设计**：在 `NativeNetworkConnectionService` 中对所有 COM 属性读取及网卡启用/禁用接口调用实施精细的 Catch 保护。如果由于系统 COM 服务繁忙返回异常，向 UI 报告失败信息并触发重试，避免直接向上抛出导致主线程崩溃。
2. **异步任务优雅取消 (CancellationToken)**
   - **设计**：在 `MainViewModel` 和 `RuleSchedulerService` 拥有的所有后台 Task（如每 5 秒的 HTTP 联网探测、流量采样等）中注入 `CancellationToken`。
   - **退出拦截**：在 `MainWindow_Closing` 事件触发时，首先触发 `Cancel()`，确保所有后台网络探测线程在毫秒级内感知并安全退出，之后立刻关闭主进程，保证“关闭即完全终结”。
3. **日志自动滚动与清理 (Log Rotation)**
   - **设计**：在 `LogService` 中新增容量清理方法。
   - **逻辑**：在程序启动时，异步扫描 `%LOCALAPPDATA%\NetRelay\logs\` 下的所有日志文件，对于超过保留天数（如 30 天）或累积大小超过设定上限的文件执行安全物理删除。

#### 验收标准
- 使用模拟错误注入测试 COM 接口异常，程序应正常运行不崩溃，并在界面提示诊断信息。
- 用户点击关闭窗口退出程序后，任务管理器中 `NetRelay.exe` 进程在 1 秒内完全消失，无残留线程。
- 手动生成 30 个历史日志文件，启动程序后，超出期限的文件能自动被清理。

### 2. 第六阶段：环境感知 (Detection) (已实现)

#### 目标
解决在校园网、企业代理或公共 Wi-Fi 重定向环境下单一 HTTP 探测可能失效（如重定向导致虚报联网）的问题。

#### 核心任务
1. **多协议网络探测 (ICMP Ping / DNS 解析)**
   - **设计**：重构 `ConnectivityService`。在 HTTP 探测的基础上，并发进行 ICMP Ping（如 Ping `223.5.5.5`）以及轻量 DNS 域名解析（如解析公共域名）。
   - **后端辅助逻辑**：在后续与后端打通时，通过向指定的后端 API 地址发送解析与握手请求，检验真实外网连通性。
2. **Windows 原生 NLM/NCSI 状态监听**
   - **设计**：通过 P/Invoke 或 .NET Native 接口，读取 Windows 的 Network List Manager，获取系统对当前活动连接的官方联网状态评估，作为辅助的决策因子。

#### 验收标准
- 在拦截 HTTP 的断网环境下，Ping 与 DNS 检测能准确判断真实断网。

### 3. 第七阶段：富交互 (Interaction) (已实现)

#### 目标
将关键调度参数和日志清理选项从文本配置文件中解放出来，提供图形化配置，并通过交互式通知提供极简的用户体验。

#### 核心任务
1. **防抖、冷却与日志清理参数 GUI 化**
   - **设计**：在 Settings 窗口中新增配置项输入滑块：
     - 网络变化判定防抖时间（秒）
     - 规则执行冷却时间（分钟）
     - 日志保留天数上限
   - **双向绑定**：将参数与 `AppConfiguration` 及 `SettingsDialog` 绑定；防抖与冷却作为新建规则默认值，日志保留天数在启动和保存设置后立即应用，保存时同步校验并重载调度器。
2. **可交互式 Windows Rich Toast 通知**
   - **设计**：利用 Windows 10/11 的 App Notification API，替代传统的托盘气泡通知。
   - **交互设计**：当规则倒计时预警发生时，屏幕右下角弹出的 Toast 根据规则权限显示 **“延迟 N 分钟”** 和 **“取消本次”** 操作按钮。点击按钮后，系统通过包含一次性动作 ID 与随机令牌的协议激活参数，在后台请求 `RuleSchedulerService` 执行对应操作。

#### 验收标准
- 设置界面的日志保留天数即时生效并持久化；防抖与冷却默认值影响后续新建规则，但不覆盖已有规则。
- 自动测试已验证 Toast 参数、权限和一次性票据逻辑；Windows 通知中心真实点击后能否保持主窗口隐藏，仍需在发布版上手动验收。

### 4. 第八阶段：交付打包 (Delivery)（进行中）

> 启动日期：2026-06-15。维护者已正式批准启动第八阶段。开发期间保持当前产品版本号不变；进入发布阶段及修改版本号仍需维护者另行明确批准。

#### 目标
完成面向大众用户的最后一步，消除绿色版在普通系统运行时的权限、配置与依赖障碍，提供零门槛的一键安装。

#### 核心任务
1. **引导式安装包制作 (WiX/Inno Setup)**
   - **设计**：编写 Inno Setup 或 WiX 项目脚本，将 Release 交付目录下的发布文件编译打包为单个安装文件 `NetRelaySetup.exe`。
2. **Windows x64 自包含交付**
   - **设计**：主程序与独立更新器携带运行所需的 .NET 组件，安装器、开发预览和在线更新包统一使用压缩单文件 `win-x64` 自包含产物，目标电脑无需预装或联网下载 .NET Desktop Runtime。
3. **一键卸载与开机自启任务清理**
   - **设计**：提供标准的添加/删除程序卸载支持。在卸载时，自动调用 Windows 任务计划程序 API，彻底清理安装时或程序内部创建的 `NetRelay AutoStart` 任务项及对应的注册表项，不留任何系统垃圾。
4. **统一交付构建与更新 ZIP**
   - **设计**：增加单一 Windows 交付构建入口，同时发布 WPF 主程序和独立更新器，生成可直接上传管理后台的 `win-x64.zip`、构建追溯信息以及安装器输入目录。
   - **安全边界**：更新 ZIP 不自行伪造签名；服务端签名清单与包哈希必须由客户端和独立更新器共同验证。

#### 验收标准
- 在一台全新未安装 .NET 的 Windows 10/11 干净虚拟机上运行安装包，无需联网下载运行时即可正常安装并启动程序。
- 在控制面板卸载程序后，应用安装文件夹、注册表项、日志及计划任务全部被彻底清除。

#### 当前实施状态（2026-06-15）
- 已新增 `deploy/windows/build-delivery.ps1`，统一生成主程序、独立更新器、`win-x64.zip` 和 `NetRelaySetup.exe`。
- 已新增 Inno Setup 安装器；客户端和独立更新器改为压缩单文件 `win-x64` 自包含发布，安装器无需 Runtime 检测与下载，并完成标准卸载、自启动任务清理、通知协议注册清理、旧版散文件清理和可选用户数据删除。
- 已加固客户端更新链路：客户端下载已验证签名清单 sidecar，独立更新器再次验证证书链、清单签名、包大小与 SHA256，并在临时目录运行以避免覆盖自身；异常路径会恢复旧文件并删除本次新增文件。
- 自动验收已通过解决方案 Release 构建、43 项客户端回归测试、25 项服务端测试、管理后台构建和 Inno Setup 6.7.3 编译。
- 阶段仍处于进行中：需完成未安装 .NET Desktop Runtime 的干净 Windows 10/11 虚拟机安装/卸载实测、真实服务端更新与回滚演练、代码签名，以及将更新清单签名从当前在线操作密钥迁移到规范要求的离线发布密钥。
- 当前 Windows 主机已完成安装、启动、自检、协议注册和选择保留用户数据的正常卸载实测；安装目录与系统集成项清理成功，配置和日志按选择保留。
- 中文安装向导、安装路径选择、开机自启动与桌面快捷方式选项已完成勾选/取消勾选实测；安装和客户端管理员权限保持为核心功能所需的强制边界。
